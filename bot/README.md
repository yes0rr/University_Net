# Чат-бот для мессенджера MAX

Компонент проекта `University_Net`: бот, через который пользователь попадает
в мини-приложение с подбором вузов и может подобрать вуз прямо в чате.

Данные — четыре города: **Москва, Санкт-Петербург, Казань, Томск**
(31 вуз, 360 направлений бакалавриата и специалитета).

## Что делает

| Действие пользователя | Ответ бота |
|---|---|
| `/start` | приветствие и меню |
| `/help` | список команд |
| `/cities` | панель с четырьмя городами |
| `/scores` | подбор по баллам: пять шагов |
| `/cancel` | сбросить диалог |
| кнопка **«Подобрать по баллам»** | город → уровень → направление → форма обучения → сумма баллов → проходные баллы по вузам |
| кнопка **«Города и данные»** | панель с четырьмя городами; по выбранному — вузы и число направлений |
| кнопка **«Подобрать вуз»** | открывает мини-приложение с картой и подбором по предметам ЕГЭ |
| кнопка **«Что умеет бот»** | короткая справка |
| любой другой текст | подсказка с меню |

### Подбор по баллам: пять шагов

```
Пользователь: нажимает «Подобрать по баллам»
Бот:          Шаг 1 из 5. Выберите город:
              [Москва] [Санкт-Петербург] [Казань] [Томск] [В начало]

Пользователь: [Казань]
Бот:          Шаг 2 из 5. Казань. Выберите уровень образования:
              [Бакалавриат] [Специалитет] [← Другой город] [В начало]

Пользователь: [Специалитет]
Бот:          Шаг 3 из 5. Казань, специалитет — выберите направление.
              Всего 29 направлений, страница 1 из 4.

              [03.05.01 Астрономия]           [04.05.01 Фундаментальная и прикладная х…]
              [08.05.01 Строительство уника…] [10.05.02 Информационная безопасность…]
              [14.05.02 Атомные станции…]     [20.05.01 Пожарная безопасность]
              [30.05.01 Медицинская биохимия] [31.05.01 Лечебное дело]
              [Ещё →]
              [← Другой уровень] [В начало]

Пользователь: [31.05.01 Лечебное дело]
Бот:          Шаг 4 из 5. 31.05.01 Лечебное дело, специалитет
              Выберите форму обучения: бюджет или платное.
              [Бюджет] [Платное] [← Другое направление] [В начало]

Пользователь: [Бюджет]
Бот:          Шаг 5 из 5. Напишите свою сумму баллов ЕГЭ одним числом.
              Например: 190. Максимум — 300.

Пользователь: 280
Бот:          31.05.01 Лечебное дело
              Казань · специалитет · бюджет
              Ваша сумма: 280 из 300

              Баллов хватает — 2 вуза:
              • КГМУ — 258 (запас 22)
              • КФУ — 276 (запас 4)

              Проходные баллы по этой форме указаны у 2 вузов города из 6.
              Без баллов по этой форме: КНИТУ-КАИ, КНИТУ, КГЭУ, КГАСУ.

              Предметы ЕГЭ: русский язык + химия + биология или математика (профиль).

              [Подробнее в приложении] [Показать платное]
              [Другое направление] [В начало]
```

Детали диалога:

- **Направления листаются по 8 на страницу** (в Казани 10 страниц бакалавриата
  и 4 специалитета, в Москве 9 и 3). Кнопки «← Назад» и «Ещё →» появляются
  только когда есть куда листать; подписи длинных названий обрезаются до
  45 символов, потому что лимит подписи кнопки в MAX — 128.
- **Форма обучения** выбирается на шаге 4, а в результате есть кнопка
  «Показать платное / Показать бюджет» — тот же экран пересчитывается
  по другому столбцу, без повторного ввода баллов.
- **Смена города или направления сбрасывает сумму баллов**: на новый запрос
  пользователь вводит её заново.
- **Если суммы мало**, бот пишет, где ближе всего: «Ни одному вузу этой суммы
  пока не хватает. Ближе всего КГМУ: не хватает 8».
- **Если по форме нет баллов** у части вузов, они перечисляются отдельной
  строкой — вместо невнятного «0».
- Магистратуры в подборе нет: строки уровня `xx.04.xx` отбрасываются
  при чтении файлов.

## Данные

Бот читает **те же файлы**, что и сайт: `data/spec_napr.json` плюс по файлу
на город. Правила разбора повторяют `frontend/data-loader.js` один в один —
иначе бот и сайт начали бы показывать разные баллы:

- код направления собирается из `id-1.id-2.id-3`;
- магистратура (`xx.04.xx`) отбрасывается сразу;
- `-` и пустая строка — это «нет данных», а не ноль;
- направления без единого балла в модель не попадают;
- названия вузов восстанавливаются из вложенных ключей, порядок столбцов
  сохраняется (в файле Москвы точки в названиях разложили столбцы на объекты).

Модуль разбора — `bot/vuzdata.py`, тексты ответов — `bot/admission.py`.

В Docker папка данных копируется внутрь образа: `COPY data/ /app/data/`
(см. `deploy/Dockerfile.bot`). Без этой строки подбор по баллам отвечает
ошибкой, поэтому при старте бот печатает в лог, что данные найдены:

```
Данные: /app/data
  Москва: 13 вузов, 87 направлений (Бакалавриат, Специалитет)
  Санкт-Петербург: 6 вузов, 88 направлений (Бакалавриат, Специалитет)
  Казань: 6 вузов, 103 направления (Бакалавриат, Специалитет)
  Томск: 6 вузов, 82 направления (Бакалавриат, Специалитет)
```

## Запуск

### Windows — одной кнопкой

Двойной клик по `start_bot.bat` в корне проекта. Скрипт сам создаст окружение,
установит зависимости и, если нужно, откроет блокнот для ввода токена.

### Вручную

```powershell
cd C:\Users\пк\Desktop\University_Net
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r bot\requirements.txt
python bot\bot.py
```

### Проверки

```powershell
python tools\test_bot.py        # 97 проверок: данные, подбор, тексты, диалог
node tools\test_frontend.js     # 146 проверок: интерфейс сайта
```

Тест бота работает **без сети и без токена**: отправка сообщений подменяется
заглушкой, поэтому весь диалог можно проверить до выкладки на сервер.

## Токен

Лежит в файле `bot/.env`, который не коммитится в репозиторий:

```
MAX_BOT_TOKEN=ваш_токен
MAX_BOT_NAME=t401_hakaton_max_bot
MINI_APP_URL=https://45-153-69-132.sslip.io
```

Шаблон — `bot/.env.example`.

Где взять токен: `business.max.ru` → «Чат-боты» → бот → «⋮» → Настройки.

При старте бот проверяет токен запросом `GET /me` и печатает имя бота.
Если токен неверный — выходит с понятным сообщением, а не молча падает.

## Про сертификат Минцифры

Домен `platform-api2.max.ru` защищён сертификатом `Russian Trusted Root CA`,
которого нет в стандартном наборе Python. Без него соединение падает с
`SSLError: unable to get local issuer certificate` — даже если сертификат
установлен в Windows, потому что библиотека `requests` использует собственный
набор (`certifi`), а не системный.

Поэтому сертификат лежит в `bot/certs/russian_trusted_root_ca.crt` и на старте
подмешивается к набору `certifi`. Доустанавливать ничего в систему не нужно —
работает одинаково на Windows, Linux и в Docker.

Актуальную версию сертификата можно скачать:
<https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt>

## Ограничения

- Используется **Long Polling** (`GET /updates`). Документация MAX не
  рекомендует его для production — для рабочей версии нужен Webhook, а он
  требует HTTPS и не может работать одновременно с Long Polling.
- Бот должен быть **запущен постоянно**: остановили процесс — бот не отвечает.
- Состояние диалога хранится **в памяти процесса**: после перезапуска бота
  незаконченный диалог начинается заново. Базы данных в проекте нет сознательно.
- Подбор по баллам не учитывает **предметы** ЕГЭ: он показывает проходные баллы
  выбранного направления по вузам. Подбор по предметам — в мини-приложении
  (кнопка «Подобрать вуз»).
- Балл показывается **по конкретному направлению**, а не по вузу целиком:
  у одного вуза на разных направлениях баллы разные, и это видно в результате.
- Для работы кнопки «Подобрать вуз» к боту должен быть **привязан HTTPS-адрес
  мини-приложения** в кабинете бизнеса `business.max.ru` — привязку выполняют
  организаторы хакатона. Кнопка-ссылка работает и без привязки.
