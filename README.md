# University_Net — подбор вуза по баллам ЕГЭ

**Трек:** Образовательные решения
**Чат-бот в MAX:** [@t401_hakaton_max_bot](https://max.ru/t401_hakaton_max_bot)
**Мини-приложение:** https://45-153-69-132.sslip.io

Абитуриент открывает бота в MAX, нажимает «Подобрать вуз», выбирает город,
предметы ЕГЭ или направление подготовки — и сразу видит, куда проходит,
а где баллов не хватает.

> ⚠️ **О данных.** Баллы и направления — **подготовленная выгрузка**, а не прямое
> подключение к информационной системе вуза. Источник описан в разделе 8.
> Данные используются в демонстрационных целях.

---

## 1. Назначение решения

Помочь абитуриенту ответить на вопрос «куда я прохожу с моими баллами» за один
экран, не листая сайты приёмных комиссий и не сверяя таблицы вручную.

**Проблема.** Списки направлений и проходных баллов разбросаны по сайтам вузов,
у каждого своя форма подачи, а сравнивать приходится десятки вузов и сотни
направлений одновременно. Школьник и родитель тратят на это часы, а результат
устаревает к моменту сравнения.

**Что делает решение.** Показывает карту, по клику на регион — вузы с проходными
баллами на бюджет и на платное. Два способа подбора: по предметам ЕГЭ и по
направлению подготовки; в обоих случаях по введённой сумме баллов считается
«проходит / не хватает».

**Охват.** Четыре города — Москва, Санкт-Петербург, Казань, Томск: **31 вуз и
360 направлений** бакалавриата и специалитета. Данных по другим городам нет.

**Уровень образования.** Показываются только бакалавриат и специалитет: туда
поступают по баллам ЕГЭ после 11 класса. Магистратура не показывается нигде —
приём туда идёт после диплома и по другим экзаменам.

## 2. Основной пользовательский сценарий

Сквозной путь — от запуска бота до результата:

1. Пользователь открывает бота **@t401_hakaton_max_bot** в MAX и пишет `/start`.
2. Бот отвечает приветствием и кнопкой **«Подобрать вуз»**.
3. Кнопка открывает мини-приложение с картой России.
4. Пользователь нажимает на **Республику Татарстан** (или на точку Казани).
5. В правой панели появляются **6 вузов Казани** с диапазоном проходных баллов
   по уровням: например, КФУ — бакалавриат 170–278 (47 направлений),
   специалитет 217–276 (8 направлений).
6. Пользователь отмечает предметы ЕГЭ: **математика (профиль) + информатика**.
   В панели остаются **48 направлений в 5 вузах** с лучшим баллом по каждому:
   КНИТУ 183, КФУ 185, КГЭУ 187, КНИТУ-КАИ 190, КГАСУ 192.
7. Пользователь вводит свои баллы — например, **95 + 95 = 190**.
8. Напротив четырёх вузов появляется метка **«Проходит»**, у КГАСУ —
   **«Не хватает»**.
9. Итог: пользователь видит, куда проходит, и понимает, где не дотягивает.

**Результат сценария:** список подходящих вузов с оценкой шансов.

Второй способ подбора — **по направлению подготовки**: пользователь выбирает,
например, «31.05.01 Лечебное дело», и панель показывает только те вузы, где это
направление есть, с баллом именно этого направления: Казань — КГМУ 258 и
КФУ 276, Томск — СибГМУ 255, Москва — РНИМУ 263, Первый МГМУ 292, РУДН 296,
МГУ 380.

**Путь без карты — подбор прямо в чате.** У бота есть отдельные кнопки:

1. **«Подобрать по баллам»** — пять шагов: город (четыре кнопки) → уровень
   (бакалавриат или специалитет) → направление (список со страницами по 8) →
   форма обучения (бюджет или платное) → пользователь пишет свою сумму баллов.
   Ответ: проходные баллы этого направления по вузам города — «хватает
   (запас N)» или «не хватает N», плюс перечислены вузы без баллов по этой
   форме. Кнопка «Показать платное / бюджет» пересчитывает экран без
   повторного ввода баллов.
2. **«Города и данные»** — панель с четырьмя городами; по выбранному видно
   число вузов и направлений по уровням.
3. **«Подобрать вуз»** — открывает мини-приложение с картой.

## 3. Архитектура решения

Три части, между ними — HTTPS и файлы JSON. Базы данных, очередей и внешних
API (кроме MAX) нет: сайт статический, поэтому работает быстро и не падает
вместе с чужим сервисом.

```
        MAX (мессенджер)
        пользователь → @t401_hakaton_max_bot → кнопка «Подобрать вуз»
                    │
                    │ open_app по HTTPS
                    ▼
┌───────────────────────────────────────────────────────────────────────┐
│  Контейнер university_net_web                                         │
│                                                                       │
│    Caddy :80/:443   HTTPS-сертификат Let's Encrypt + отдача статики   │
│      ├── frontend/  index.html · styles.css · russia-map.js/.svg       │
│      │              script.js · city-panel.js · data-loader.js         │
│      └── data/      spec_napr.json + 4 базы городов                    │
│                                                                       │
│    main.py          тот же сайт локально на :8000 (uvicorn, без Docker)│
└───────────────────────────────────────────────────────────────────────┘
        ▲
        │ fetch data/*.json — прямо из браузера, без промежуточного API
        │
┌───────────────────────────────────────────────────────────────────────┐
│  Контейнер university_net_bot                                         │
│    bot/bot.py       long polling GET /updates к platform-api2.max.ru   │
│                     /start, /help, кнопка-ссылка на мини-приложение    │
└───────────────────────────────────────────────────────────────────────┘
        │
        │ HTTPS, цепочка проверяется корневым сертификатом Минцифры
        ▼
  MAX Bot API (platform-api2.max.ru)
```

| Компонент | Что делает | Где код | Состояние |
|---|---|---|---|
| Мини-приложение | Карта, панель вузов, оба подбора, калькулятор ЕГЭ | `frontend/` | Работает в MAX и в браузере |
| Локальный сервер | Отдаёт то же самое на `127.0.0.1:8000` без Docker | `main.py` | Для разработки и проверки |
| Бот | Приветствие и кнопка входа в мини-приложение | `bot/bot.py` | Работает в MAX |
| Данные | Четыре базы городов + справочник | `data/*.json` | Читаются браузером напрямую |
| Развёртывание | Два контейнера одной командой | `compose.yaml`, `deploy/` | HTTPS выпускается сам |

**Почему так, а не иначе.**

- **Сайт без бэкенда.** Все расчёты — фильтрация, сортировка, сравнение баллов —
  идут в браузере по правилам из `frontend/data-loader.js`. Сервер только отдаёт
  файлы. Это убирает целый слой, который мог бы упасть на защите, и делает
  проект запускаемым без Docker одной командой.
- **Один источник правды — папка `data/`.** Второй копии данных в коде нет:
  правка JSON видна после перезагрузки страницы.
- **Бот не читает данные.** Он отвечает текстом и открывает приложение, поэтому
  на его стороне нет риска разойтись с сайтом в цифрах.
- **Базы не смешиваются.** У каждого города свой файл: новый город — это строка
  в реестре `CITY_REGISTRY` и файл в `data/`, код панели не меняется.

**Чего в архитектуре сознательно нет:** базы данных, авторизации, MAX Bridge
и обращений к информационным системам вузов — данные подготовленные, это
заявлено в разделе 14.

## 4. Запуск всех компонентов одной командой

Нужен установленный Docker с плагином compose.

```bash
cp .env.example .env     # указать DOMAIN
cp bot/.env.example bot/.env   # указать MAX_BOT_TOKEN
docker compose up -d --build
```

Эта команда поднимает **оба** компонента решения:

| Контейнер | Что делает |
|---|---|
| `university_net_web` | Статика мини-приложения + HTTPS-сертификат |
| `university_net_bot` | Чат-бот MAX (long polling) |

Приложение — на `https://<DOMAIN>`, бот — в MAX. Отдельных шагов для запуска
бота не требуется: он стартует тем же `compose`.

> Контейнеризация **не заменяет** работу в MAX: бот и мини-приложение остаются
> доступны пользователю в мессенджере, см. раздел 11.
>
> Сборка при первом запуске занимает **меньше 5 минут** (без учёта скачивания
> базовых образов).

## 5. Необходимые параметры окружения

### Корневой `.env` (рядом с `compose.yaml`)

| Переменная | Обязательна | Что означает |
|---|---|---|
| `DOMAIN` | да | Публичный адрес мини-приложения, например `45-153-69-132.sslip.io`. Обратите внимание: **без** `https://`. |

### `bot/.env` (рядом с `bot.py`)

| Переменная | Обязательна | Что означает |
|---|---|---|
| `MAX_BOT_TOKEN` | да | Токен бота из кабинета MAX. Секрет. |
| `MAX_BOT_NAME` | нет | Публичное имя бота — `t401_hakaton_max_bot`. Без него не появится кнопка «Открыть в MAX». |
| `MINI_APP_URL` | нет | Адрес стенда для кнопки «Подобрать вуз». По умолчанию — боевой адрес. |

Оба файла **не входят в репозиторий** (см. `.gitignore`) — в репозитории лежат
только `.env.example` и `bot/.env.example` с пояснениями. В `.dockerignore`
исключены `.env`, `bot/.env`, `*.pem`, `*.key`, поэтому секреты не попадают
в образы при сборке.

### Локальный запуск без Docker

| Переменная | Что означает |
|---|---|
| — | не требуются: сервер читает данные из `data/*.json` |

## 6. Используемые порты

| Порт | Где | Зачем |
|---|---|---|
| **80** | контейнер `web` | Приём запросов; Caddy перенаправляет на HTTPS (код 308) |
| **443** | контейнер `web` | HTTPS. Сертификат Let's Encrypt выпускается автоматически |
| **8000** | локальный запуск (`uvicorn`) | `http://127.0.0.1:8000` — разработка без Docker |
| — | контейнер `bot` | **Входящие порты не нужны:** бот сам опрашивает MAX (long polling) |

Наружу на сервере открыты 22 (SSH), 80 и 443. Бот слушает только исходящие
соединения к `platform-api2.max.ru`.

## 7. Зависимости

### Бот — `bot/requirements.txt`

```
requests>=2.31          HTTP-запросы к MAX Bot API
certifi>=2024.0.0       набор корневых сертификатов
python-dotenv>=1.0      чтение bot/.env
```

Корневой сертификат **Russian Trusted Root CA** Минцифры лежит в репозитории
(`bot/certs/russian_trusted_root_ca.crt`): цепочка `platform-api2.max.ru`
заканчивается на нём, и без него Python не доверяет сертификату API. Код
склеивает его с `certifi` во время старта.

### Локальный сервер — `requirements.txt`

```
fastapi                 API и раздача статики
uvicorn[standard]       ASGI-сервер
```

Данные лежат в `data/*.json` и читаются браузером напрямую — отдельного шага
сборки данных нет, поэтому `openpyxl` и прочие библиотеки для Excel не нужны.

### Образы Docker

| Образ | Роль |
|---|---|
| `caddy:2-alpine` | Веб-сервер + автоматический HTTPS |
| `python:3.12-slim` | Среда бота |

Фронтенд — **чистый HTML/CSS/JS без сборки и без внешних CDN**: карта России
встроена в страницу, поэтому приложение работает и без интернета.

к платёжным сервисам.

## 9. Описание работы с данными

> ⚠️ **Данные подготовленные.** Баллы и направления — выгрузка, а не прямое
> подключение к информационной системе вуза. Прямого подключения к ИС вуза
> в MVP **нет** — это заявленное допущение, а не скрытая замена интеграции.

| Файл | Содержимое | Роль |
|---|---|---|
| `data/spec_napr.json` | Справочник: код направления → название, уровень образования, укрупнённая группа | Расшифровка кодов |
| `data/moscow.json` | 13 вузов Москвы, 87 направлений после 11 класса | База города |
| `data/spb.json` | 6 вузов Санкт-Петербурга, 88 направлений | База города |
| `data/kazan_2026.json` | 6 вузов Казани, 103 направления | База города |
| `data/tomsk.json` | 6 вузов Томска, 82 направления | База города |
| `Vuzanet(1).xlsx` | Исходная таблица, с которой начинали | Архив источника |

Сводной базы `frontend/data.js` и генератора `tools/build_tomsk_data.py` больше
нет: данные читаются только из `data/`, и новых городов в коде тоже нет.

**Как устроена база города.** Одна строка — одно направление:

| Столбец | Что означает |
|---|---|
| `id-1`, `id-2`, `id-3` | Код направления: `01.03.01` — бакалавриат, `01.05.01` — специалитет |
| `пред обяз` | Обязательный предмет ЕГЭ |
| `пред 1`, `пред 2` | Предметы на выбор — достаточно сдать один из двух |
| `бю <вуз>` | Проходной балл на бюджет |
| `пл <вуз>` | Проходной балл на платное; `-` значит «нет данных» |

Русский язык обязателен для всех направлений и в базе не хранится.

**Магистратура в подбор не попадает.** Строки уровня «Магистратура» (коды
`xx.04.xx`) отбрасываются при разборе файла. Их нет ни в панели, ни в счётчиках,
ни в боте: приём в магистратуру идёт после диплома и по другим экзаменам,
а баллы ЕГЭ к нему не относятся.

**Бот читает те же файлы.** Модуль `bot/vuzdata.py` повторяет правила разбора
`frontend/data-loader.js` один в один — иначе бот и сайт показывали бы разные
баллы. Проверка на одних и тех же числах — в `tools/test_bot.py`. В Docker
данные копируются в образ бота (`COPY data/ /app/data/`), поэтому подбор
в чате работает даже при недоступном сайте.

**Персональные данные не собираются.** Авторизации в системе нет: ни на сайте,
ни в боте не запрашиваются логин, пароль или телефон, и данные пользователя
никуда не передаются.

## 10. Порядок загрузки и обработки данных

```
data/spec_napr.json ─┐
                     ├─► frontend/data-loader.js  (fetch при открытии страницы)
data/<город>.json ───┘
                     │
                     ▼
Панель: «01.03.01» → «Математика» из справочника,
        «бю КФУ» → число, «-» → нет данных,
        {"бю МГУ им": {" М": {"В": {" Ломоносова": ...}}}} → «бю МГУ им. М.В. Ломоносова»
```

1. **Доставка.** Файлы `frontend/` и `data/` копируются в контейнер `web`
   на этапе сборки образа; сервер отдаёт их как статику.
2. **Загрузка.** При клике по городу `data-loader.js` запрашивает
   `data/spec_napr.json` и файл этого города.
3. **Нормализация.** Код направления собирается из `id-1.id-2.id-3`, строковые
   баллы превращаются в числа, `-` — в «нет данных», предметы — в подписи
   из справочника.
4. **Отбор.** Магистратура и направления без единого балла отбрасываются.
5. **Отрисовка.** Панель наполняется; работают оба подбора и сортировка
   по баллам.
6. **Кэш.** Страница и код отдаются с `Cache-Control: no-cache`, в ссылках стоит
   метка версии `?v=5`, а внизу панели — подпись сборки: если браузер подсунул
   старый файл из кэша, это видно сразу.

Правки в `data/*.json` видны после перезагрузки страницы — пересборка не нужна.
Если `fetch` не сработал (страница открыта двойным кликом как файл), загрузчик
пишет об этом прямым текстом, а не молчит.

## 11. Пошаговый сценарий проверки

Проверяющему достаточно открыть бота в MAX. Ручной запуск Docker не требуется.

### Проверка в MAX (основной путь)

1. Открыть **https://max.ru/t401_hakaton_max_bot**
2. Отправить **`/start`** — придут кнопки «Подобрать по баллам»,
   «Города и данные», «Подобрать вуз», «Что умеет бот»
3. Проверить подбор в чате: **«Подобрать по баллам»** → **Казань** →
   **Специалитет** → листать до **31.05.01 Лечебное дело** → **Бюджет** →
   написать **280**. Бот ответит: хватает КГМУ (258, запас 22) и КФУ (276,
   запас 4); у КНИТУ-КАИ, КНИТУ, КГЭУ и КГАСУ по этой форме баллов нет
4. Нажать **«Города и данные»** → **Москва** → 13 вузов, 87 направлений
5. Нажать **«Подобрать вуз»** — откроется мини-приложение с картой
   (если адрес уже привязан к боту организаторами)
6. В приложении: нажать на **Республику Татарстан** → в панели 6 вузов Казани
7. Отметить предметы **математика (профиль) + информатика** → 48 направлений
   в 5 вузах (КНИТУ 183, КФУ 185, КГЭУ 187, КНИТУ-КАИ 190, КГАСУ 192)
8. Ввести баллы **95 + 95** → у четырёх вузов «Проходит», у КГАСУ «Не хватает»
9. Проверить второй подбор: направление **«31.05.01 Лечебное дело»** → панель
   оставляет только вузы с этим направлением

### Проверка развёртывания с нуля (для технической оценки)

На чистом сервере Ubuntu от пользователя `root`:

```bash
# 1. Получить код
git clone https://github.com/yes0rr/University_Net.git /opt/app && cd /opt/app

# 2. Заполнить окружение
cp .env.example .env                    # DOMAIN=<IP с дефисами>.sslip.io
```

## 13. Известные ограничения

**Данные**

- Данные **подготовленные** (выгрузка), а не полученные из ИС вуза в реальном
  времени. Обновление — правкой `data/*.json`, без автоматической синхронизации.
- Базы собраны по четырём городам: Москва, Санкт-Петербург, Казань, Томск.
  Данных по другим городам нет и не будет — это осознанное сужение охвата
  ради глубины по каждому городу.
- Не все направления заполнены баллами. Строки, где у всех вузов стоит `-`,
  в панель не попадают: Казань — 25 таких строк, Санкт-Петербург — 40,
  Москва — 41, Томск — 46.
- **Аномальные значения в исходных файлах** (данные такого вида не правим,
  а фиксируем — при сверке с сайтами приёмных комиссий это первое, что нужно
  проверить):
  - баллы выше 300 (максимум ЕГЭ по трём предметам — 300): Москва — 48 значений
    (МГУ 37, в том числе 02.03.02 — 469 на бюджете при 186 на платном; РУДН 5;
    МГИМО 4; НИУ ВШЭ 2), Томск — 3 (ТГУ 42.03.02 — 364, ТГУ 54.03.01 — 340,
    ТГАСУ 07.03.01 — 309), Санкт-Петербург — 2 (СПбГУ 54.03.01 платное — 390,
    СПбГАСУ 07.03.01 платное — 332); в Казани таких значений нет;
  - платные баллы ниже 120 у бакалавриата и специалитета: Казань — 25,
    Москва — 41, Санкт-Петербург — 9, Томск — 4. Вероятная причина — баллы
    относятся к другому набору предметов или учитывают скидку по олимпиаде;
  - в `data/moscow.json` точки в названиях вузов разложили столбцы во вложенные
    объекты (2352 поля вида `{"бю МГУ им": {" М": {"В": {" Ломоносова": "-"}}}}`).
    Загрузчик склеивает их обратно, поэтому в интерфейсе всё корректно, но сам
    файл лучше привести к плоскому виду.
- Магистратура в исходных файлах есть (68 строк уровня `xx.04.xx` в каждом
  файле), но в подбор не попадает: баллы ЕГЭ к ней не относятся.

**Функциональность**

- Балл направления показывается по каждому вузу отдельно; при переключателе
  «Платное» берётся столбец платного приёма, а если его нет — вуз помечается
  как «нет данных по этой форме обучения».
- В подборе по предметам на карточке вуза видны три направления и строка
  «и ещё N»; полный список — это следующий шаг развития.
- Авторизации нет совсем: личный кабинет не предусмотрен, персональные данные
  не запрашиваются и не сохраняются.
- В приложении нет авторизации через MAX Bridge и валидации `initData`:
  персональные данные не запрашиваются, поэтому проверять подпись нечего.

**Организационные**

- Ник публичного бота не меняется после создания (ограничение платформы).
- Привязка URL мини-приложения к боту выполняется на стороне организаторов
  через форму сбора ссылок, командой изменить её нельзя.
- Мини-приложение работает в веб-версии MAX и в мобильном приложении;
  отдельного нативного клиента нет.

**Риски**

| Риск | Что делаем |
|---|---|
| Сервер недоступен | `restart: unless-stopped` — контейнеры поднимаются автоматически |
| Не выпустился сертификат | Caddy повторяет попытку; при блокировке портов 80/443 выпуск невозможен |
| Пропал доступ к MAX API | Бот пишет ошибку в лог и продолжает попытки; сайт работает независимо |
| Устаревание данных | Данные лежат в JSON — обновление без пересборки кода |
| Старые файлы из кэша браузера | `no-cache` для HTML/JS/CSS, метка `?v=5` и подпись сборки внизу панели |

## 14. Порядок остановки и повторного запуска

```bash
# Остановить всё (контейнеры удаляются, данные и сертификаты сохраняются)
docker compose down

# Снова запустить
docker compose up -d
```

Тома `caddy_data` и `caddy_config` при `down` **не удаляются** — сертификат
Let's Encrypt сохраняется, повторный запуск не приводит к лишнему запросу
к серверу сертификации.

```bash
# Полная остановка с удалением томов (сертификат будет выпущен заново)
docker compose down -v

# Логи
docker compose logs -f          # все контейнеры
docker compose logs -f bot      # только бот

# Перезапуск
docker compose restart

# Обновление после правок кода
git pull && docker compose up -d --build
```

```

data/                четыре базы городов + справочник направлений (источник правды)
bot/                 чат-бот MAX: bot.py, зависимости, корневой сертификат Минцифры
deploy/              Caddyfile и Dockerfile-ы
tools/               автотесты: test_frontend.js (сайт), test_bot.py (бот),

compose.yaml         запуск всех компонентов одной командой
deploy.sh            развёртывание на чистом сервере Ubuntu «под ключ»
main.py              локальный сервер разработки (FastAPI)
```
