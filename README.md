# University_Net — подбор вуза по баллам ЕГЭ

**Трек:** Образовательные решения
**Чат-бот в MAX:** [@t401_hakaton_max_bot](https://max.ru/t401_hakaton_max_bot)
**Мини-приложение:** https://45-153-69-132.sslip.io

Абитуриент открывает бота в MAX, нажимает «Подобрать вуз», выбирает направление
подготовки и свои баллы ЕГЭ — и сразу видит, куда проходит, а где баллов
не хватает.

> ⚠️ **О данных.** Баллы и направления — **подготовленная выгрузка**, а не прямое
> подключение к информационной системе вуза. Источник описан в разделе 8.
> Данные используются в демонстрационных целях.

---

## 1. Назначение решения

Помочь абитуриенту Томска ответить на вопрос «куда я прохожу с моими баллами»
за один экран, не листая сайты приёмных комиссий и не сверяя таблицы вручную.

**Проблема.** Списки направлений и проходных баллов разбросаны по сайтам вузов,
у каждого своя форма подачи, а сравнивать приходится 6 вузов и 81 направление
одновременно. Школьник и родитель тратят на это часы, а результат устаревает
к моменту сравнения.

**Что делает решение.** Показывает карту, по клику на регион — вузы с проходными
баллами, фильтрует по направлению подготовки и считает «проходит / не хватает»
по введённой сумме баллов.

---

## 2. Основной пользовательский сценарий

Сквозной путь — от запуска бота до результата:

1. Пользователь открывает бота **@t401_hakaton_max_bot** в MAX и пишет `/start`.
2. Бот отвечает приветствием и кнопкой **«Подобрать вуз»**.
3. Кнопка открывает мини-приложение с картой России.
4. Пользователь нажимает на **Томскую область** (или на точку Томска).
5. В правой панели появляются **6 вузов Томска** с диапазоном проходных баллов.
6. Пользователь выбирает **направление подготовки** — например,
   «31.05.01 Лечебное дело». Список сокращается до **4 вузов**, у которых это
   направление есть, они сортируются по проходному баллу: 180, 190, 230, 238.
7. Пользователь вводит **сумму баллов ЕГЭ** — например, 200.
8. Напротив каждого вуза появляется метка **«Проходит»** или **«Не хватает N»**.
9. Итог: пользователь видит вузы, куда проходит, и понимает, сколько баллов
   не дотягивает до остальных.

**Результат сценария:** список подходящих вузов с оценкой шансов.

## 3. Запуск всех компонентов одной командой

Нужен установленный Docker с плагином compose.

```bash
cp .env.example .env     # указать DOMAIN
cp bot/.env.example bot/.env   # указать MAX_BOT_TOKEN
docker compose up -d --build
```

Эта команда поднимает **оба** компонента решения:

| Контейнер | Что делает |
|---|---|
| `university_net_web` | Статика мини-приложения + HTTPS-сертификат |
| `university_net_bot` | Чат-бот MAX (long polling) |

Приложение — на `https://<DOMAIN>`, бот — в MAX. Отдельных шагов для запуска
бота не требуется: он стартует тем же `compose`.

> Контейнеризация **не заменяет** работу в MAX: бот и мини-приложение остаются
> доступны пользователю в мессенджере, см. раздел 10.
>
> Сборка при первом запуске занимает **меньше 5 минут** (без учёта скачивания
> базовых образов).

## 4. Необходимые параметры окружения

### Корневой `.env` (рядом с `compose.yaml`)

| Переменная | Обязательна | Что означает |
|---|---|---|
| `DOMAIN` | да | Публичный адрес мини-приложения, например `45-153-69-132.sslip.io`. Обратите внимание: **без** `https://`. |

### `bot/.env` (рядом с `bot.py`)

| Переменная | Обязательна | Что означает |
|---|---|---|
| `MAX_BOT_TOKEN` | да | Токен бота из кабинета MAX. Секрет. |
| `MAX_BOT_NAME` | нет | Публичное имя бота — `t401_hakaton_max_bot`. Без него не появится кнопка «Открыть в MAX». |
| `MINI_APP_URL` | нет | Адрес стенда для кнопки «Подобрать вуз». По умолчанию — боевой адрес. |

Оба файла **не входят в репозиторий** (см. `.gitignore`) — в репозитории лежат
только `.env.example` и `bot/.env.example` с пояснениями. В `.dockerignore`
исключены `.env`, `bot/.env`, `*.pem`, `*.key`, поэтому секреты не попадают
в образы при сборке.

### Локальный запуск без Docker

| Переменная | Что означает |
|---|---|
| — | не требуются: сервер читает данные из `data/*.json` |

## 5. Используемые порты

| Порт | Где | Зачем |
|---|---|---|
| **80** | контейнер `web` | Приём запросов; Caddy перенаправляет на HTTPS (код 308) |
| **443** | контейнер `web` | HTTPS. Сертификат Let's Encrypt выпускается автоматически |
| **8000** | локальный запуск (`uvicorn`) | `http://127.0.0.1:8000` — разработка без Docker |
| — | контейнер `bot` | **Входящие порты не нужны:** бот сам опрашивает MAX (long polling) |

Наружу на сервере открыты 22 (SSH), 80 и 443. Бот слушает только исходящие
соединения к `platform-api2.max.ru`.

## 6. Зависимости

### Бот — `bot/requirements.txt`

```
requests>=2.31          HTTP-запросы к MAX Bot API
certifi>=2024.0.0       набор корневых сертификатов
python-dotenv>=1.0      чтение bot/.env
```

Корневой сертификат **Russian Trusted Root CA** Минцифры лежит в репозитории
(`bot/certs/russian_trusted_root_ca.crt`): цепочка `platform-api2.max.ru`
заканчивается на нём, и без него Python не доверяет сертификату API. Код
склеивает его с `certifi` во время старта.

### Локальный сервер и генератор — `requirements.txt`

```
fastapi                 API и раздача статики
uvicorn[standard]       ASGI-сервер
openpyxl                чтение Vuzanet(1).xlsx (только генератор)
```

### Образы Docker

| Образ | Роль |
|---|---|
| `caddy:2-alpine` | Веб-сервер + автоматический HTTPS |
| `python:3.12-slim` | Среда бота |

Фронтенд — **чистый HTML/CSS/JS без сборки и без внешних CDN**: карта России
встроена в страницу, поэтому приложение работает и без интернета.

## 7. Внешние сервисы и интеграции

| Сервис | Зачем | Что нужно | Что будет без него |
|---|---|---|---|

к платёжным сервисам.

## 8. Описание работы с данными

> ⚠️ **Данные подготовленные.** Баллы и направления взяты из выгрузки
> `Vuzanet(1).xlsx`, предоставленной команде. Прямого подключения к
> информационной системе вуза в MVP **нет** — это заявленное допущение,
> а не скрытая замена реальной интеграции.

| Файл | Содержимое | Роль |
|---|---|---|
| `Vuzanet(1).xlsx` | Исходная таблица: баллы вузов по комбинациям предметов | Источник |
| `data/tomsk.json` | 34 комбинации предметов, 81 направление, 6 вузов | **Источник правды для сервера** |
| `data/subj.json` | Справочник направлений: `ID-001` → «09.03.04 Программная инженерия» | Расшифровка кодов |
| `frontend/data.js` | Те же данные + логика панели | Офлайн-копия для запуска без сервера |

**Структура.** Балл хранится по паре *(комбинация предметов × вуз)*:
русский язык обязателен и в комбинации не входит, остальные предметы
закодированы (`мат`, `инфа`, `ин-яз`). Направление однозначно определяет
комбинацию, поэтому пользователь выбирает направление, а предметы
подставляются автоматически.

**Персональные данные не собираются.** Регистрация на сайте — демонстрационная,
данные пользователей не передаются на сервер и не сохраняются.

## 9. Порядок загрузки и обработки данных

```
Vuzanet(1).xlsx
      │  tools/build_tomsk_data.py   (читает таблицу)
      ▼
frontend/data.js  ─── офлайн-копия: работает при открытии index.html двойным кликом
      │
      │  (та же выгрузка, вручную приведённая к JSON)
      ▼
data/tomsk.json + data/subj.json
      │  frontend/tomsk-loader.js    (fetch при загрузке страницы)
      ▼
Панель: строки "230" → числа, "—" → null, "ID-001" → название направления
```

1. **Сборка.** `python tools/build_tomsk_data.py` читает xlsx и записывает
   `frontend/data.js`.
2. **Доставка.** В контейнер `web` файлы `frontend/` и `data/` копируются
   на этапе сборки образа.
3. **Загрузка.** При открытии страницы `tomsk-loader.js` запрашивает
   `data/tomsk.json` и `data/subj.json` через `fetch`.
4. **Нормализация.** Строковые баллы → числа, `"—"` → `null`,
   идентификаторы → читаемые названия.
5. **Отрисовка.** Панель наполняется; сортировка и фильтрация — по направлению
   и по введённой сумме баллов.

Если `fetch` не сработал (страница открыта как файл), загрузчик пишет
предупреждение в консоль, и панель продолжает работать на данных `data.js`.

Правки в `data/*.json` видны после перезагрузки страницы — пересборка не нужна.

## 10. Пошаговый сценарий проверки

Проверяющему достаточно открыть бота в MAX. Ручной запуск Docker не требуется.

### Проверка в MAX (основной путь)

1. Открыть **https://max.ru/t401_hakaton_max_bot**
2. Отправить **`/start`**
3. Нажать кнопку **«Подобрать вуз»** — откроется мини-приложение с картой
4. Нажать на **Томскую область** → в панели 6 вузов
5. Выбрать направление **«31.05.01 Лечебное дело»** → остаётся 4 вуза
   (180, 190, 230, 238)
6. Ввести сумму баллов **200** → появится метка «Не хватает» / «Проходит»

### Проверка развёртывания с нуля (для технической оценки)

На чистом сервере Ubuntu от пользователя `root`:

```bash
# 1. Получить код
git clone https://github.com/yes0rr/University_Net.git /opt/app && cd /opt/app

# 2. Заполнить окружение
cp .env.example .env                    # DOMAIN=<IP с дефисами>.sslip.io
cp bot/.env.example bot/.env            # MAX_BOT_TOKEN=<токен бота>

# 3. Поднять всё одной командой
docker compose up -d --build

# 4. Убедиться, что оба контейнера работают
docker compose ps
```

Ожидаемо: через 30–60 секунд (выпуск сертификата) адрес из `DOMAIN`
отвечает по HTTPS, бот отвечает на `/start` в MAX.

### Автотесты фронтенда

```bash

```

50 проверок: клик по точке Томска **и по Томской области**, наполнение панели,
фильтрация и сортировка вузов по направлению, отбрасывание вузов без
направления, расчёт баллов, метки «Проходит / Не хватает», лимит 100
и прозрачный ноль в полях ЕГЭ, переключатель бюджет/платное, работа остальных
городов, а также разбор JSON загрузчиком.

## 12. Известные ограничения

**Данные**

- Данные **подготовленные** (выгрузка), а не полученные из ИС вуза в реальном
  времени. Обновление — пересборкой `data/*.json`, без автоматической синхронизации.
- Балл хранится по паре *(комбинация предметов × вуз)*, а не *(направление × вуз)*.
  Поэтому направления внутри одной комбинации дают одинаковый проходной балл:
  «Программная инженерия» и «Лесное дело» (обе — мат/инфа) показывают одни числа.
  Чтобы развести их, нужен столбец баллов на каждое направление.
- В таблице одна цифра на вуз, без разделения бюджет/платное. При переключателе
  «Платное» показывается тот же балл с пометкой.
- Подробные данные собраны по **Томску**. Для остальных городов на карте
  работает демонстрационный набор; полноценные базы в работе.

**Функциональность**

- Поиск по направлениям и предметам — в разработке (`мин. баллы` по направлению
  и подбор по предметам ЕГЭ).
- Данных по городам, кроме планируемых, на сайте не будет — это осознанное
  сужение охвата ради глубины по каждому городу.
- Регистрация пользователя демонстрационная — личный кабинет не сохраняется.
- В приложении нет авторизации через MAX Bridge и валидации `initData`:
  персональные данные не запрашиваются, поэтому проверять подпись нечего.

**Организационные**

- Ник публичного бота не меняется после создания (ограничение платформы).
- Привязка URL мини-приложения к боту выполняется на стороне организаторов
  через форму сбора ссылок, командой изменить её нельзя.
- Мини-приложение работает в веб-версии MAX и в мобильном приложении;
  отдельного нативного клиента нет.

**Риски**

| Риск | Что делаем |
|---|---|
| Сервер недоступен | `restart: unless-stopped` — контейнеры поднимаются автоматически |
| Не выпустился сертификат | Caddy повторяет попытку; при блокировке портов 80/443 выпуск невозможен |
| Пропал доступ к MAX API | Бот пишет ошибку в лог и продолжает попытки; сайт работает независимо |
| Устаревание данных | Данные лежат в JSON — обновление без пересборки кода |

## 13. Порядок остановки и повторного запуска

```bash
# Остановить всё (контейнеры удаляются, данные и сертификаты сохраняются)
docker compose down

# Снова запустить
docker compose up -d
```

Тома `caddy_data` и `caddy_config` при `down` **не удаляются** — сертификат
Let's Encrypt сохраняется, повторный запуск не приводит к лишнему запросу
к серверу сертификации.

```bash
# Полная остановка с удалением томов (сертификат будет выпущен заново)
docker compose down -v

# Логи
docker compose logs -f          # все контейнеры
docker compose logs -f bot      # только бот

# Перезапуск
docker compose restart

# Обновление после правок кода
git pull && docker compose up -d --build
```
